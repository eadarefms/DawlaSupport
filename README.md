# منصة الدعم التربوي عن بعد — المستويات الإشهادية
### الأكاديمية الجهوية للتربية والتكوين مراكش آسفي — مصلحة التعلم والتكوين عن بعد

تسليم كامل للمشروع عبر 8 مراحل: البنية والمصادقة، اقتراح الحصص ومنع التعارض،
تسجيل التلاميذ، البريد والتذكيرات، الساعات والشهادات، لوحات القيادة، PDF/Excel،
وإعدادات النظام والإشعارات. راجع `docs/ARCHITECTURE.md` للتفاصيل الكاملة لكل مرحلة.

⚠️ **ملاحظة صريحة حول بيئة البناء**: تم تطوير هذا المشروع في بيئة بلا اتصال
بخوادم Prisma (`binaries.prisma.sh`)، لذا لم أتمكن من تشغيل `prisma generate`
فعليًا هناك ولا من التحقق من الأنواع الكاملة لطلبات قاعدة البيانات (كانت تُفحص
مقابل نوع عام بديل). تحققت من سلامة الكود عبر تجميع TypeScript الكامل ومراجعة
يدوية دقيقة لكل استعلام مقابل `schema.prisma`، لكن هذا لا يغني عن تشغيل
`npm run prisma:generate` و`npm run prisma:migrate` على جهازك (بوصول اعتيادي
للإنترنت) كخطوة أولى، والتأكد من استقرار كل شيء قبل النشر.

## 1. المتطلبات
- Node.js 18 أو أحدث
- PostgreSQL 14 أو أحدث (مجاني ومفتوح المصدر) — محليًا أو عبر خدمة مجانية مثل
  [Neon](https://neon.tech) أو [Supabase](https://supabase.com) (لا تتطلب بطاقة بنكية للطبقة المجانية)

## 2. إعداد قاعدة البيانات

```bash
# أنشئ قاعدة بيانات محلية (مثال بـ psql)
createdb dawla_support
```

أو استعمل رابط اتصال جاهز من Neon/Supabase.

## 3. تشغيل الـ Backend

```bash
cd backend
npm install
cp .env.example .env
# عدّل DATABASE_URL و JWT_SECRET داخل .env، وأضف إعدادات البريد إن رغبت

npm run prisma:generate
npm run prisma:migrate     # ينشئ الجداول (سيطلب اسم migration، اكتب مثلاً: init)
npm run prisma:seed        # يزرع المديريات/المستويات/الشعب/المواد + حسابات تجريبية

npm run dev                # يشغّل الخادم على http://localhost:4000
```

تحقق من عمل الخادم عبر: `GET http://localhost:4000/health`

### حسابات تجريبية (بعد تشغيل prisma:seed)
| الدور | اسم المستخدم | كلمة المرور |
|---|---|---|
| مسؤول النظام | `admin` | `Passw0rd!` |
| رئيس المصلحة | `chef.service` | `Passw0rd!` |
| منسق إقليمي (مراكش) | `coord.marrakech` | `Passw0rd!` |
| أستاذ | `T12345` | `Passw0rd!` |
| تلميذ | `M2026001` | `Passw0rd!` |

### تفعيل البريد الإلكتروني (اختياري)
إن تُرك `EMAIL_HOST` فارغًا في `.env`، تُطبع رسائل التذكير في سجل الخادم بدل
إرسالها فعليًا (آمن للتجربة المحلية). لتفعيل الإرسال الحقيقي، استعمل أي مزود
SMTP مجاني (مثل Gmail App Password أو Brevo) وعبّئ `EMAIL_HOST`/`EMAIL_USER`/
`EMAIL_PASSWORD` في `.env`.

### تفعيل PDF الرسمي (خطوة يدوية لمرة واحدة)
PDFKit لا يشحن بخط عربي افتراضيًا. نزّل ملف TTF مجاني يدعم العربية (Amiri أو
Noto Naskh Arabic أو Cairo) وضعه في `backend/assets/fonts/arabic.ttf` — راجع
`backend/assets/fonts/README.md` للتفاصيل والروابط.

## 4. تشغيل الـ Frontend

```bash
cd frontend
npm install
npm run dev                # يشغّل على http://localhost:5173
```

الواجهة تتصل بالخادم عبر بروكسي Vite (`/api` → `http://localhost:4000`).

## 5. ما هو جاهز (المراحل 1 إلى 8 مكتملة)

- **المرحلة 1 — الأساسيات**: قاعدة بيانات كاملة، تسجيل/دخول الأستاذ والتلميذ
  (JWT + bcrypt)، صلاحيات الأدوار الخمسة (RBAC) مع عزل حسب المديرية، بيانات
  مرجعية (مديريات/مستويات/شعب/مواد)، واجهة RTL بهيكل Sidebar/Topbar، بيانات تجريبية.
- **المرحلة 2 — الحصص واستعمال الزمن**: اقتراح حصة مع حساب المدة تلقائيًا، منع
  تاريخ سابق/الأسبوع الحالي، منع تعارض التوقيت (فحص منطقي + قيد قاعدة بيانات)،
  معاينة استعمال الزمن قبل التأكيد، عرض أسبوعي بفلاتر وتنقل بين الأسابيع.
- **المرحلة 3 — تسجيل التلاميذ**: دروس متاحة حسب المستوى/الشعبة، تسجيل بمعلومات
  كاملة، منع التسجيل المزدوج (قيد قاعدة بيانات)، "دروسي"، "التلاميذ المستفيدون".
- **المرحلة 4 — البريد والتذكيرات**: مزود بريد قابل للتبديل (SMTP أو وضع تجريبي)،
  Cron Job كل ساعة يرسل تذكيرًا 24 ساعة قبل كل حصة للأستاذ وكل التلاميذ المسجلين،
  مع علامة `reminderSent` لمنع الإرسال المكرر.
- **المرحلة 5 — الساعات والشهادات**: احتساب تلقائي لساعات كل أستاذ من الحصص
  المكتملة، إصدار شهادة تقديرية تلقائيًا كل 10 ساعات (مع دعم تجاوز عدة عتبات
  دفعة واحدة)، صفحة تقدّم للأستاذ، ولائحة الأساتذة المستحقين للمنسق/رئيس المصلحة.
- **المرحلة 6 — لوحات القيادة**: لوحة الأستاذ (KPIs + الحصة القادمة)، لوحة
  المنسق الإقليمي (معزولة تلقائيًا على مديريته + توزيع حسب المستوى)، اللوحة
  الجهوية لرئيس المصلحة/المسؤول (مقارنة المديريات الثمانية).
- **المرحلة 7 — PDF وExcel**: تصدير Excel للتلاميذ المستفيدين/الأساتذة/الحصص
  (ExcelJS، ترويسات عربية)، وتوليد PDF رسمي للبرمجة الأسبوعية (PDFKit) بترويسة
  وشعار الأكاديمية — يتطلب إضافة ملف خط عربي مرة واحدة (راجع القسم 3 أعلاه).
- **المرحلة 8 — الإعدادات والإشعارات**: صفحة إعدادات للمسؤول (اسم الأكاديمية/
  المصلحة، معلومات التواصل، السنة الدراسية النشطة مع إمكانية إنشاء سنوات جديدة
  دون حذف القديمة)، ونظام إشعارات داخل التطبيق (تسجيل جديد، قبول/إلغاء حصة،
  استحقاق شهادة) مع تعليم كمقروء.

## 6. تحسينات مستقبلية غير حرجة للنسخة الأولى
- تشكيل نصوص عربي كامل (Arabic shaping/bidi) داخل PDF لضبط اتصال الحروف تمامًا.
- رفع شعار الأكاديمية كملف (حاليًا حقل رابط/مسار فقط).
- استيراد Excel/CSV للبيانات (Import) — التصدير جاهز، الاستيراد لم يُبنَ بعد.
- تكامل حقيقي مع Microsoft Teams/Google Meet عبر MeetingProvider (حاليًا رابط يدوي).
- تطبيقات Android/iOS، إشعارات Push، WhatsApp، تسجيل الحضور، تقييم الحصص.

## 8. ملاحظات أمنية
- لا توجد أي أسرار داخل الكود؛ كل شيء عبر `.env`.
- كلمات المرور مشفّرة بـ bcrypt (12 rounds).
- كل طلب API محمي بمصادقة JWT + RBAC على مستوى الخادم.
- منع الازدواجية (رقم تأجير/رمز مسار/تسجيل مزدوج/تعارض توقيت) مضمّن كقيود
  فريدة (`@@unique`) في قاعدة البيانات نفسها، وليس فقط تحققًا في الواجهة.
- التصدير والتقارير محمية بنفس صلاحيات RBAC (لا تصدير بيانات مديرية أخرى للمنسق).
